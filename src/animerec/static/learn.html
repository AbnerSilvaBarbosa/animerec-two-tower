01 · A IDEIA

Duas torres, um espaço em comum

Uma rede olha para você (gêneros que curte, nota média, quanto já assistiu) e cospe um vetor. Outra olha para cada anime (gêneros, tipo, episódios, popularidade) e também cospe um vetor. As duas aprendem a colocar quem combina perto. Recomendar vira achar os vizinhos mais próximos.

Experimente: escolha gêneros

Escolha ao menos um gênero.
Como o último passo das torres é UnitNormalization, todo vetor tem tamanho 1: usuários e animes moram num círculo (aqui em 2D; no projeto, uma esfera de 64D). Só o ângulo importa.
02 · SIMILARIDADE

Cosseno vira probabilidade

O modelo calcula o cosseno entre o vetor do usuário u e o do anime v, e passa por uma sigmoide: P(gostar) = σ(a·cos(u,v) + b). Arraste o vetor do usuário e mexa em a e b.

Um bug de verdade: no primeiro treino deste projeto, o peso a saiu −3,18. O AUC ficou ótimo (0,83), mas o ranking ficou invertido: quanto mais parecido, menos chance de gostar. O Recall@20 do modelo foi 0% contra 13% de "só os mais populares". A correção foi travar a ≥ 0 com NonNeg().
03 · SPLIT

Separe antes de calcular qualquer coisa

Média, desvio, vocabulário: tudo que o .adapt() aprende deve vir só do treino. Se o teste entra na conta, ele "vaza" e a métrica final mente. O split é por usuário, então o teste são pessoas que o modelo nunca viu.

04 · NO GRAFO

05 · MÉTRICAS

AUC e Recall@K contam histórias diferentes

AUC é a chance de uma nota "gostou" receber score maior que uma "não gostou". Recall@K pergunta outra coisa: dos que a pessoa gostou, quantos aparecem no seu top-K? Dá para ter AUC alto e Recall baixo.

06 · BUSCA VETORIAL

Achar vizinhos sem olhar para todo mundo

Comparar o usuário com os 12 mil animes funciona, mas não escala para milhões. O índice HNSW do pgvector monta camadas de atalhos: salta longe nas camadas de cima e refina na de baixo. Clique no mapa para mudar a consulta e veja quantas distâncias cada método calcula.

camada 2 (poucos pontos, saltos longos)camada 1camada 0 (todos)consulta

distâncias — HNSW—
-- 1 − distância cosseno = score; o índice HNSW acelera o ORDER BY
CREATE INDEX animes_emb_hnsw ON animes USING hnsw (embedding vector_cosine_ops);
SELECT name, 1 - (embedding <=> :user_vec) AS score FROM animes
ORDER BY embedding <=> :user_vec LIMIT 12;
